# Contexte Historique

## Histoire de l'Origine

p2d2 est né de la constatation que les données administratives et les données des citoyens existent souvent en parallèle sans échange systématique. Les autorités maintiennent leurs données spécialisées, tandis que les citoyens saisissent les mêmes informations dans OpenStreetMap ou WikiData.

## Le Problème

- **Travail en Double** : Les mêmes données sont collectées plusieurs fois
- **Incohérences** : Les données administratives et les données de la communauté se contredisent
- **Manque d'Actualité** : Les changements dans un système n'atteignent pas l'autre
- **Gaspillage de Ressources** : L'administration et la communauté travaillent séparément

## La Vision

p2d2 comble cette lacune grâce à un **flux de données bidirectionnel** :

- Les données administratives sont fournies en tant que Données Ouvertes
- Les citoyens peuvent vérifier, corriger et utiliser ces données
- Les améliorations reviennent dans les systèmes administratifs
- Nous bénéficions tous de données de qualité garantie : citoyens souverains en matière de données, nos administrations et notre économie, car nous basons nos décisions sur des faits que chacun peut vérifier par lui-même.

## Projet Pilote : Cimetières à Cologne

Le premier scénario d'application était la collecte de données sur les cimetières à Cologne :

- **Situation Initiale** : Les données des cimetières étaient disponibles dans des systèmes spécialisés mais pas dans OSM
- **Défi** : Même si le conseil municipal de Cologne a défini _"toutes les données comme fondamentalement publiques"_ en 2010 et 2012, les données dans les applications spécialisées résident souvent dans des silos de données et sont protégées du public.
- **Succès** : Transfert systématique et synchronisation continue

## Développement Ultérieur

Du projet pilote s'est développée une infrastructure de données géospatiales générique qui peut être mise à l'échelle pour différentes catégories de données et zones géographiques.
