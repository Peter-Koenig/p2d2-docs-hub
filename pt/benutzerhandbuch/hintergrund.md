# Contexto Histórico

## História da Origem

O p2d2 surgiu da percepção de que os dados administrativos e os dados dos cidadãos frequentemente existem em paralelo sem troca sistemática. As autoridades mantêm seus dados especializados, enquanto os cidadãos inserem as mesmas informações no OpenStreetMap ou WikiData.

## O Problema

- **Trabalho Duplicado**: Os mesmos dados são coletados várias vezes
- **Inconsistências**: Dados administrativos e dados da comunidade se contradizem
- **Falta de Atualidade**: Alterações em um sistema não chegam ao outro
- **Desperdício de Recursos**: Administração e comunidade trabalham separadamente

## A Visão

O p2d2 fecha essa lacuna através de um **fluxo de dados bidirecional**:

- Dados administrativos são fornecidos como Dados Abertos
- Os cidadãos podem revisar, corrigir e usar esses dados
- Melhorias fluem de volta para os sistemas administrativos
- Todos nós nos beneficiamos de dados com qualidade garantida: cidadãos soberanos de dados, nossas administrações e nossa economia, porque baseamos nossas decisões em fatos que todos podem verificar por si mesmos.

## Projeto Piloto: Cemitérios em Colônia

O primeiro cenário de aplicação foi a coleta de dados de cemitérios em Colônia:

- **Situação Inicial**: Dados de cemitérios estavam disponíveis em sistemas especializados, mas não no OSM
- **Desafio**: Mesmo que o conselho municipal de Colônia tenha definido _"todos os dados como fundamentalmente públicos"_ em 2010 e 2012, dados em aplicações especializadas frequentemente residem em silos de dados e são protegidos do público.
- **Sucesso**: Transferência sistemática e sincronização contínua

## Desenvolvimento Adicional

Do projeto piloto, desenvolveu-se uma infraestrutura de dados geoespaciais genérica que pode ser dimensionada para diferentes categorias de dados e áreas geográficas.
